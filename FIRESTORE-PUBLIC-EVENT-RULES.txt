PowerDink v3.7.8 — Firestore rules needed for public event viewing + view analytics

Paste these in Firebase Console > Firestore Database > Rules, then Publish.

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    // Guests can view events. Logged-in users can update events for the current signup system.
    match /events/{eventId} {
      allow read: if true;
      allow write: if request.auth != null;
    }

    // Guests can read the published appearance/content only.
    match /siteSettings/{document=**} {
      allow read: if true;
      allow write: if request.auth != null;
    }

    // Guests may only CREATE anonymous view records. They cannot read/update/delete them.
    match /publicViews/{viewId} {
      allow create: if request.resource.data.keys().hasOnly(['eventId','visitorId','path','source','createdAt'])
                    && request.resource.data.eventId is string
                    && request.resource.data.visitorId is string
                    && request.resource.data.path is string
                    && request.resource.data.source is string;
      allow read: if request.auth != null;
      allow update, delete: if false;
    }

    // Everything else remains account-only, matching the app's existing security model.
    match /{document=**} {
      allow read, write: if request.auth != null;
    }
  }
}

Notes:
- Public views store only a random browser visitor ID, event ID, source (direct/facebook), page path, and timestamp.
- No guest name/email is collected for views.
- The dashboard starts collecting NEW activity after v3.7.8 is deployed; it cannot reconstruct old guest views that were never logged.
